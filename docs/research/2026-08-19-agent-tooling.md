# מחקר R15 - סקילים וכלים קיימים לשיפור סוכן הפיתוח

**תאריך המחקר:** 19.8.2026.
**נושא באג'נדה:** R15. **בקשת מייסד מפורשת.**

**מה נבדק:** מה מותקן היום בריפו, מה זמין ולא בשימוש, ומה שווה להוסיף - בדגש על מה שאוכף
את כללי הברזל של הפרויקט **מכנית במקום במשמעת**.

---

## 1. מצב הריפו היום

| מה | מצב |
|---|---|
| `.claude/settings.json` (הגדרות פרויקט משותפות) | **לא קיים** |
| `.claude/settings.local.json` | קיים. שתי הרשאות בלבד: `WebSearch` ו-`WebFetch(developers.google.com)`; שרת supabase מנוטרל |
| סקילים ברמת הפרויקט | **אין** |
| hooks | **אין** |
| `.mcp.json` | supabase + vercel. **שניהם דורשים אימות ואינם פעילים בסשן הזה** |
| `CLAUDE.md` | קיים ומפורט |

**הממצא המרכזי בסעיף הזה:** כל ההגדרות יושבות ב-`settings.local.json`, שהוא **קובץ אישי
ואינו משותף**. בפרויקט שבו עובד גם סוכן של השותף (`agent-reports/`), **כל מה שנלמד על
הרשאות והתנהלות נשאר אצל מי שהגדיר אותו.** קובץ `settings.json` ברמת הפרויקט הוא הפער הבסיסי.

## 2. ההזדמנות הגדולה: להפוך כללי ברזל לאכיפה אוטומטית

ל-`CLAUDE.md` יש כללי ברזל שהפרתם מוגדרת כבאג. **שניים מהם ניתנים לאכיפה מכנית, ואינם נאכפים
היום** - הם נשענים על כך שהסוכן יזכור.

### 2.1 תווים אסורים - הפער הכי גלוי

הכלל: מקף ארוך, שלוש נקודות כתו יחיד, אמוג'י ותווי כיווניות אסורים **בכל טקסט: קוד, הערות,
UI ו-DB**. היום זה נאכף בשלוש דרכים חלקיות: `normalizeTypography` על פלט LLM בזמן ריצה,
בדיקות יחידה על תוויות הבנק, ובדיקה ידנית בשערי אבן דרך.

**מה שחסר: אכיפה על כל קובץ שנכתב.** hook מסוג PostToolUse שרץ אחרי כתיבה או עריכה, סורק
את הקובץ בקודפוינטים מפורשים, ומחזיר שגיאה בהפרה - **הופך כלל ברזל מהבטחה לעובדה.**

**וזה מגובה בניסיון מר מתועד:** בשער אבן דרך 4 סקריפט בדיקת התווים דיווח 155 הפרות שווא,
כי התו הליטרלי בתוך הסקריפט עצמו הידרדר לרווח רגיל. **הלקח כבר נרשם שם ויושם גם היום בכל
בדיקות המסמכים של הסבב הזה: כל תו מוגדר בבריחת יוניקוד מפורשת, לעולם לא מודבק כתו.**
כל hook שייבנה חייב להיכתב כך.

### 2.2 `prisma migrate reset` - כלל שאסור להסתמך בו על זיכרון

הכלל: **לעולם לא להריץ**, כי ה-DB מכיל את הקטלוג והבנצ'מרקים שנחקרו ידנית ואין להם קיצור דרך.
זהו בדיוק סוג הפקודה שנראית תמימה כשמשהו נתקע.

**המלצה: hook מסוג PreToolUse שחוסם את הפקודה.** עלות: שורות בודדות. תוחלת הנזק שהוא מונע:
כל המחקר הידני שנצבר. **זו ההמלצה בעלת יחס הערך-לסיכון הטוב ביותר במסמך.**

### 2.3 מועמד שלישי, חלש יותר

`npm run build` בזמן ששרת dev רץ - שניהם על `.next` והבנייה קורסת. ניתן לחסום, אבל הזיהוי
(האם dev רץ?) פחות טריוויאלי, והנזק הפיך. **לא מומלץ בשלב זה.**

## 3. סקילים זמינים - מה רלוונטי לריפו הזה

| סקיל | רלוונטיות | הערה |
|---|---|---|
| **`code-review`** | **גבוהה** | הפרויקט מקיים "מקסימום סבב סקירה אחד למשימה". סקיל ייעודי מייעל בדיוק את הסבב הזה |
| **`security-review`** | **גבוהה** | הפרויקט השקיע בהגנות SSRF, וכל מקור חדש (TLS, כותרות, Overture) הוא משטח תקיפה חדש. R13 מוסיף כמה כאלה |
| **`simplify`** | **גבוהה** | תואם ישירות לכלל "שימוש חוזר לפני יצירה" - הכלל שהכי קשה לאכוף בעין |
| `claude-api` | בינונית | היום הספק הוא Gemini. **יהפוך רלוונטי במבחן ה-A/B של R4**, שכולל מודלים של Claude |
| `run` | בינונית | יש `npm run dev`; ה-QA בדפדפן נדחה במכוון לשלב העיצוב |
| `fewer-permission-prompts` | בינונית | ייצר allowlist לפרויקט - ומתחבר ישירות לפער `settings.json` מסעיף 1 |
| `init` | לא | `CLAUDE.md` קיים ומפורט |
| `frontend-design`, `design`, `dataviz` | נמוכה עכשיו | **יהפכו רלוונטיים בשלב העיצוב**, שנדחה במכוון |

**סוכני משנה זמינים:** `Explore` (חיפוש קריאה-בלבד), `Plan` (תכנון), `general-purpose`.
בסבב המחקר של היום `Explore` שימש למיפוי הקוד והחזיר מיפוי מלא של הצינור, הקטלוג והראיון -
**שימוש מוצלח ומתועד.**

## 4. שני MCP מוגדרים ולא פעילים

`supabase` ו-`vercel` מוגדרים ב-`.mcp.json` **ושניהם דורשים אימות שלא בוצע.** בנוסף,
`supabase` מנוטרל במפורש ב-`settings.local.json`.

**זה מצב לא ברור שכדאי להכריע:** או שמאמתים ומשתמשים, או שמסירים. הגדרה שלא עובדת היא רעש
שגורם לכל סשן להתחיל בהודעת שגיאה.

**הערה על supabase:** בהינתן כלל הברזל על ה-DB, **גישת MCP ישירה למסד היא בדיוק המקום שבו
נדרשת זהירות.** אם מאמתים, כדאי במפורש רק ליכולות קריאה ותיעוד.

## 6. מה שהמסמך הזה לא עשה

- **לא נבדק מרקטפלייס תוספים חיצוני.** הסקירה כיסתה את מה שזמין בסביבה ואת מה שמוגדר בריפו.
- **לא נכתב אף hook.** ההמלצות הן תיאור, לא מימוש - וזה בהתאם להיקף שנקבע (מחקר בלבד).
- **לא נבדק** האם השותף משתמש באותה סביבה או בכלים אחרים. זה משנה מהותית את הערך של המלצה 3,
  ושווה לברר לפני ביצוע.
